# App C API

The full contract, with comments, is in `components/appfw/include/app.h` and `appmgr.h`. Here is a summary for app authors; the procedure is in [Add an app](../how-to/add-an-app.md).

## Descriptor

```c
struct app_desc {
    const char *id;            // used in config.lua (autorun.app)
    const char *name;          // name in the launcher
    const gfx_icon_t *icon;    // 12x12 icon, drawn 2x
    uint32_t accent;           // UI and LED accent color
    uint32_t requires;         // mask of app_req_t
    usb_profile_t usb;         // USB profile while the app runs (mask of USB_F_*)
    uint32_t stack;            // task stack in bytes
    void (*run)(app_ctx_t *ctx);
    void (*subtitle)(char *buf, size_t len);   // optional: line below the name
};
```

`requires`: `APP_REQ_SD` (SD mounted as FAT on `/sd`), `APP_REQ_CARD` (card present, even if not FAT), `APP_REQ_NET` (will use WiFi), `APP_REQ_BLE` (reserved). If a requirement is missing, `appmgr_unavailable()` returns the reason and the launcher does not start the app.

USB profiles (`usbdev.h`): a profile is the mask of interfaces, `USB_F_KBD`, `USB_F_MOUSE`, `USB_F_CDC` and the disk in one of two modes, `USB_F_DISK_RW` (SD to the host for reading and writing, the firmware does not see it) or `USB_F_DISK_RO` (SD read-only for the host, the firmware keeps it mounted). The predefined ones: `USB_PROFILE_NONE` (TinyUSB off, USB-Serial-JTAG comes back), `USB_PROFILE_HID` (keyboard + mouse + CDC), `USB_PROFILE_HID_DISK` (keyboard + read-only disk + CDC, no mouse), `USB_PROFILE_MSC` (read-write disk). With `CONFIG_GRILLO_USB_DEBUG_CDC` the CDC is added to every profile. Combinations with more than 4 IN endpoints (keyboard + mouse + disk + CDC) are rejected with `ESP_ERR_NOT_SUPPORTED`.

To change profile while the app runs: `esp_err_t app_usb_apply(usb_profile_t p)`. It hands the SD to the host or takes it back according to the disk mode; if the new profile fails, TinyUSB stays off and the SD returns to the firmware. Do not call `usbdev_apply` directly: it does not move the SD.

## Lifecycle

`run(ctx)` runs in a dedicated task. When it returns, the app has ended and the system automatically releases: USB profile, lent or shared SD, the app's LED layer, network leases taken by the app task. An app can do this earlier on its own.

`ctx->arg` is the launch argument (for autorun, the script path); it can be `NULL`.

An app that modifies `/config.lua` calls `app_config_changed()`: the system reloads it when the app exits, not immediately, because reloading frees the `config_str` strings that running apps are using.

## Events

```c
bool app_next_event(app_ctx_t *ctx, app_event_t *ev, uint32_t timeout_ms);
bool app_should_exit(app_ctx_t *ctx);
void app_post(app_ctx_t *ctx, app_ev_type_t type, int32_t arg);
void app_cancel_exit(app_ctx_t *ctx);
```

Types: `APP_EV_CLICK`, `APP_EV_DOUBLE`, `APP_EV_LONG`, `APP_EV_EXIT` (3 s hold: terminate as soon as possible), `APP_EV_USB`, `APP_EV_NET`, `APP_EV_TICK` and `APP_EV_USER` (generated by the app with `app_post`, useful from timers and secondary tasks), `APP_EV_ANSWER` (answer given from outside to the open dialog: `app_menu*` takes it as the item index, `app_confirm*` as no/yes, `app_message` closes; outside a dialog it is discarded). With `APP_EV_ANSWER` a web page answers the dialogs of the same display, and the first answer wins.

`APP_EV_EXIT` is delivered even if the queue is full when it arrives. `app_post(ctx, APP_EV_EXIT, 0)` is also the way to request exit from inside the app (for example from a timeout timer): it sets `exit_requested` and closes open dialogs. `app_cancel_exit` cancels a request already received, when the app decides to stay (the user answers "No" to "Exit?", or the hold only interrupted a job), and discards the EXITs still in the queue.

Exit reaches the app only when it waits for an event. If the app does not go back to waiting within 3 seconds of the request, the system offers a reboot with a second hold.

## Blocking dialogs

- `app_menu(ctx, title, items, n, selected)`: click = down, double = up, long = choose; returns the index or -1 if the app must exit. The selected row that does not fit the display scrolls horizontally: one second pause, then to the end, one second pause, from the start. The other rows stay truncated with an ellipsis.
- `app_menu_ex(...)`: as above, with a text column to the right of each row.
- `app_menu_timeout(..., timeout_ms)`: like `app_menu_ex`; with no gestures before the deadline it returns the selected item. The remaining seconds are in the title; a click stops them.
- `app_confirm(ctx, title, text, default_yes)`.
- `app_confirm_timeout(ctx, title, text, default_yes, timeout_ms)`: as above; if there is no gesture within `timeout_ms` (0 = never) it returns the default. A click disables the deadline.
- `app_message(ctx, title, text, color)`: waits for a click or long press.

In dialogs, long text scrolls by itself. Events the dialog does not use (USB, network, TICK, USER) go back into the queue when it closes, in order of arrival. When it closes, the bar title reverts to the previous one.

## Drawing

The screen is 160x80. A 12-pixel status bar plus an accent line belong to the system; the area below (from `UI_CONTENT_Y`) belongs to the app.

```c
ui_begin();            // takes the lock, clears the content area
...                    // gfx_* and ui_draw_*
ui_end();              // redraws the bar, sends the frame
```

Primitives: `gfx_text`, `gfx_text_aligned`, `gfx_text_scaled`, `gfx_text_fit`; `ui_draw_row`, `ui_draw_list`, `ui_draw_progress`, `ui_draw_pager`, `ui_draw_wrapped`, `ui_draw_hint`, `ui_toast`. Palette and constants in `ui.h`. The font is unscii, generated by `tools/gen_font.py`.

Scrolling text: `ui_scroll_t`. For text that might not fit the area, instead of truncating it:

```c
ui_scroll_t sc;
ui_scroll_init(&sc, &gfx_font_small, x, y, w, lines, text);
for (;;) {
    ui_begin(); ui_scroll_draw(&sc, UI_TEXT); ui_end();
    app_event_t ev;
    if (!app_next_event(ctx, &ev, ui_scroll_wait_ms(&sc))) { ui_scroll_tick(&sc); continue; }
    ...                // ui_scroll_step(&sc) for a manual step
}
```

## Network

```c
esp_err_t app_net_acquire(app_ctx_t *ctx, net_mode_t mode, uint32_t timeout_ms); // with network choice
esp_err_t net_acquire(net_mode_t mode, uint32_t timeout_ms);   // NET_AUTO | NET_STA | NET_AP | NET_SCAN
void net_release(void);                                        // one lease of the calling task
void net_get_info(net_info_t *info);                           // up, mode, ssid, ip, rssi, clients, trusted
esp_netif_t *net_sta_netif(void);                              // STA interface: IP, gateway, DNS, MAC
int net_scan(net_ap_t *out, int max);                          // visible networks, strongest first
const char *net_auth_name(uint8_t auth);                       // "WPA2", "open"...
```

Requests are reference-counted (leases): WiFi stays on as long as there is at least one lease. A lease belongs to the task that takes it, so it must be released by the same task; the ones the app task leaves open are released by the system on exit. If the user requests exit while `app_net_acquire` waits for the connection, the wait is interrupted and the function returns `ESP_ERR_NOT_FINISHED`. `NET_AUTO` uses a known network, otherwise it creates the hotspot. With several known networks visible, `app_net_acquire` shows a menu (RSSI, 6 seconds, then the strongest) and returns `ESP_ERR_NOT_FINISHED` if the user exits; `net_acquire` always takes the strongest. Open networks are not supported. `NET_SCAN` turns on the radio in STA mode without connecting: it is enough for `net_scan()` (about 2 seconds, at most 40 networks). `net_scan()` works with a `NET_SCAN` or `NET_STA` lease, not with the hotspot. A `NET_SCAN` lease is compatible with an already active STA connection, not vice versa.

## Web server and QR code

For apps driven by a web page (components `websrv`, `qr`, `webui`, `webtheme` and `webjson`; the examples are `apps/webhid`, `apps/webinjector` and `apps/webfiles`):

```c
esp_err_t websrv_start(const websrv_config_t *cfg); // pin, stack_size, max_frame, on_message, on_auth, on_session_end
esp_err_t websrv_add_page(const char *uri, const char *type, const uint8_t *gz, size_t len); // page already gzipped
esp_err_t websrv_add_file(const char *uri, const char *type, const uint8_t *data, size_t len, unsigned flags); // WEBSRV_GZIP, WEBSRV_CACHE
esp_err_t websrv_add_route(const httpd_uri_t *uri);  // custom route: not protected by the PIN
bool websrv_authorized(httpd_req_t *req);           // does the request carry the session token?
bool websrv_query(httpd_req_t *req, const char *key, char *out, size_t len); // decoded parameter
bool websrv_is_client(httpd_req_t *req);             // does the request come from the authenticated client?
void websrv_reply(httpd_req_t *req, const char *msg); // WebSocket message to the client
esp_err_t websrv_send(const char *msg);              // to the authenticated client, from any task
const char *websrv_client_ip(void);                  // "" if nobody is connected
bool websrv_stopping(void);                          // check in long on_message jobs
void websrv_stop(void);

bool qr_draw(const char *text, int x, int y, int box);  // between ui_begin and ui_end
void qr_wifi_text(char *out, size_t len, const char *ssid, const char *pass); // QR to join the hotspot

void webui_make_pin(const char *pin_key, char *pin, size_t len);      // 6 digits, or "" (key false or trusted network)
void webui_draw_connecting(const gfx_icon_t *icon, uint32_t accent);  // network search
void webui_draw_main(const net_info_t *ni, const char *pin, int page, const char *client, uint32_t accent); // QR, IP, PIN
esp_err_t webtheme_register(void);                   // /theme.css, /theme.js, /grillo.svg, /fonts/*
```

The server serves at most 8 files including the page, plus 8 routes added with `websrv_add_route`. `webtheme_register` (after `websrv_start`) adds the common theme: the page includes it with `<link rel="stylesheet" href="/theme.css">` and `<script src="/theme.js"></script>`, sets `--acc` to the app color and puts `<img class="logo" src="/grillo.svg">` and the `<button id="theme" class="chip">` button that switches mode in the header. The theme only governs the look; the layout stays with the page.

The server has two fixed routes: `/cfg` tells the page whether the PIN is needed, `/ws` is the WebSocket (handshake rejected if the `Origin` header is not the dongle's page). The PIN is chosen with `webui_make_pin("<app>.pin", ...)` after `app_net_acquire`: it is empty if the key is `false` or if the network is marked `trusted` in `config.lua` (`net_info_t.trusted`). The first message must be `p<PIN>`; the replies and the rules (per-address lockout, one session at a time, takeover from the same IP) are in [WebSocket protocol](websocket-protocol.md). After authentication every text message reaches `on_message`, in the server task: a long job blocks the other requests and must stop when `websrv_stopping()` becomes true. A route added with `websrv_add_route` is not protected: the handler calls `websrv_authorized` before doing anything. The token reaches the page after the PIN (`T<token>`) and changes on every login. For JSON messages there is `webjson` (`jb_begin`, `jb_kstr`, `jb_kint`, `jb_kbool`, `jb_end`), which replaces invalid UTF-8 bytes: the browser would close the WebSocket. `on_session_end` is called when the client leaves, when another one replaces it and on every `websrv_stop`: it is the place to release what the session held (Web HID releases the keys).
